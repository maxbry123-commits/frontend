## Método de trabajo

`INPUT literal → SHERIFF → VALIDATOR → RESEARCH → RANK → EXECUTE → SENTINEL → VERIFY → SUPERVISOR/JUDGE/GUARDIAN → GAP? RESEARCH con delta distinto → CODA → verify_final`

Reglas:
- una instrucción = un nodo;
- `REUSE > COPY > PATCH > ADAPTER > GENERATE`;
- sin evidencia real no existe VERIFIED;
- retry cognitivo exige `StrategyDelta` distinto;
- el agente/LLM no autoriza su propio PASS;
- memoria y router existentes se conectan por adapters;
- Stabilize CORE será el owner del workflow backend nuevo;
- el runtime fuente se conserva como arquitectura/método de referencia y no debe sobrescribir Stabilize.
